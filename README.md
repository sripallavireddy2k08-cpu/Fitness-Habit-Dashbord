# Fitness Habit Dashboard — HabitFlow

A beginner-friendly full-stack app for building and tracking everyday fitness habits. Users can register, create their own routine, check habits off each day, view past check-ins, and archive or delete habits. Data is saved in Supabase PostgreSQL.

## Problem and objectives

Fitness intentions are easy to forget when they are not part of a simple routine. HabitFlow makes progress visible without requiring a wearable, paid service, or external API. It is designed as a learning project for first-year B.Tech students.

## Features

- Email/password registration and login.
- Private user accounts and habits.
- Create, edit, archive, restore, and delete habits.
- Categories, daily targets, and accent colors.
- Daily check-ins with one record per habit per date.
- Overview metrics and recent weekly check-ins.
- Date-based activity history.
- Search and active/archived filtering.
- Responsive layout, accessible labels, empty states, and inline feedback.

No admin role is needed for this MVP. Fitness advice, wearable syncing, reminders, and social sharing are not implemented.

## Technology

- HTML5, CSS3, Vanilla JavaScript
- Node.js 20+ and Express 5
- Supabase PostgreSQL via `@supabase/supabase-js`
- `bcryptjs` for password hashing; `jsonwebtoken` for signed sessions
- Helmet, rate limiting, dotenv, and Git

## Setup from an empty folder

### 1. Create/open the project

Create a folder named `fitness-habit-dashboard`, open it in VS Code, and create the folders/files shown above. Paste the provided project source into the matching files.

### 2. Create a Supabase project

1. Sign in to Supabase and choose **New project**.
2. Choose an organization, project name, strong database password, and region.
3. Wait until the project is ready.
4. In the project dashboard, open **SQL Editor → New query**.
5. Paste the complete contents of `database/schema.sql` and click **Run**.
6. Open **Table Editor** and confirm `app_users`, `habits`, and `habit_logs` exist.

This app uses its own account table rather than Supabase Auth. Express performs password hashing and authentication. Database access is through the server-only service-role key; do not put that key in frontend files.

### 3. Configure backend environment variables

In the `backend` folder, copy `.env.example` to a new file named `.env`. In PowerShell, from the project root:
```powershell
Copy-Item backend/.env.example backend/.env
```
In VS Code, edit `backend/.env`:
```dotenv
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
SUPABASE_SERVICE_ROLE_KEY=PASTE_YOUR_SERVER_ONLY_SERVICE_ROLE_KEY
JWT_SECRET=REPLACE_WITH_A_LONG_RANDOM_SECRET_AT_LEAST_32_CHARACTERS
```
Find the project URL and server-side service-role key in the Supabase dashboard's API/project settings. Supabase may label newer privileged credentials as secret keys; use the supported server-only key appropriate to your project. Never share it, put it in browser code, or commit it to Git.

Generate a random JWT secret from a terminal:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```
Copy the output into `JWT_SECRET`. `.env` contains your real local settings and must remain private. `.env.example` contains placeholders and belongs in Git.

### 4. Install dependencies

Open the VS Code terminal at the project root and run:
```bash
cd backend
npm install
```
npm installs the packages listed in `package.json` and creates `package-lock.json`. Successful output ends with a package summary; warnings about funding are not fatal. Do not upload `node_modules`.

### 5. Start the app

From the `backend` directory:
```bash
npm run check
npm start
```
The syntax check should finish without errors. The server should print:
`Fitness Habit Dashboard running at http://localhost:3000`

Open **http://localhost:3000** in your browser. Do not open `frontend/index.html` directly; the app uses Express API routes.

Check the database connection at `http://localhost:3000/api/health`. A working connection returns `{"status":"ok","database":"connected"}`.

## Architecture

Browser HTML/CSS/JavaScript calls `/api/...` using `fetch`. Express validates each request, verifies a signed 12-hour JWT for private routes, and talks to Supabase PostgreSQL with a server-only key. The browser keeps the token in `sessionStorage`, so it is cleared when that browser tab session ends. Passwords are hashed with bcrypt and never returned by the API.

Because the backend uses a privileged database key, authorization is enforced in Express and every habit/log query filters by the verified user's ID. RLS is enabled and direct `anon`/`authenticated` table grants are revoked. This is a small teaching MVP; for production, prefer Supabase Auth or server-managed secure cookies, add CSRF protections where relevant, stronger monitoring, and formal security review.

## API reference

All request and response bodies are JSON. Private endpoints require `Authorization: Bearer <token>`.

| Method | Path | Purpose | Auth |
|---|---|---|---|
| GET | `/api/health` | Server and DB health check | No |
| POST | `/api/auth/register` | Create account; body: `{name,email,password}` | No; rate-limited |
| POST | `/api/auth/login` | Sign in; body: `{email,password}` | No; rate-limited |
| GET | `/api/auth/me` | Current account | Yes |
| GET | `/api/habits` | List current user's habits | Yes |
| POST | `/api/habits` | Create habit; body: `{name,category,target,color}` | Yes |
| PATCH | `/api/habits/:id` | Edit fields or archive/restore with `{archived:true/false}` | Yes, owner only |
| DELETE | `/api/habits/:id` | Delete habit and logs | Yes, owner only |
| POST | `/api/habits/:id/check-in` | Upsert check-in; body: `{date:"YYYY-MM-DD",completed:true}` | Yes, owner only |
| GET | `/api/logs?date=YYYY-MM-DD` | Logs for one date | Yes |
| GET | `/api/logs?from=YYYY-MM-DD&to=YYYY-MM-DD` | Logs in inclusive date range | Yes |

Typical success responses include `{ "user": {...} }`, `{ "habits": [...] }`, or `{ "logs": [...] }`. Errors use a JSON `{ "error": "..." }` body and HTTP status codes such as 400, 401, 404, 409, and 500.

## Using the app

1. Create an account from the registration tab.
2. Select **New habit**, give it a name, category, and optional target.
3. On Overview, press the round check button when you complete the habit.
4. Use My habits to edit, search, archive/restore, or delete habits.
5. Use Activity history to choose a date and see which active habits were completed.
6. Sign out using the arrow icon beside your profile.

## Testing checklist

- [ ] `/api/health` reports database connected.
- [ ] A new valid account registers and lands on the dashboard.
- [ ] Registering the same email again returns a duplicate-email message.
- [ ] Incorrect login credentials are rejected.
- [ ] A valid habit persists after refreshing the browser.
- [ ] Blank/one-character habit names are rejected.
- [ ] A check-in changes today's completion count and appears in history.
- [ ] Editing and archiving/restoring a habit works.
- [ ] Deleting a habit asks for confirmation and removes its logs.
- [ ] Search and active/archived filters work.
- [ ] Unauthenticated requests to `/api/habits` and `/api/logs` return 401.
- [ ] A user cannot modify another user's habit by guessing its ID.
- [ ] The dashboard remains usable at phone, tablet, and desktop widths.

These are instructions for checks to run locally; no remote Supabase instance is preconfigured or verified by this package.

## Troubleshooting

- **`Missing SUPABASE_URL...`**: verify `backend/.env` exists and variable names match exactly; restart Node after edits.
- **Health endpoint says database unavailable**: check the project URL/key, confirm the SQL ran, and ensure the Supabase project is not paused.
- **`Invalid API key` or permission errors**: copy the server-only key from the correct Supabase project. Never use a browser key as the service key.
- **Port in use**: change `PORT=3001` in `.env`, restart, and open `http://localhost:3001`.
- **`Cannot find module`**: run `npm install` from `backend`.
- **401 after being idle**: the 12-hour token expired; sign in again.
- **Page opens but styles are missing**: open the site through Express at `http://localhost:3000`, not by double-clicking the HTML file.
- **PowerShell copy command fails**: create `backend/.env` manually by copying the contents of `.env.example`.

## Git and GitHub

1. Create an empty repository on [GitHub](https://github.com/new). Do not add a README there if you already have this one.
2. In VS Code, open a terminal at the project root:
```bash
git init
git status
git add .
git status
git commit -m "Build Fitness Habit Dashboard"
git branch -M main
git remote add origin YOUR_GITHUB_REPOSITORY_URL
git push -u origin main
```
Replace `YOUR_GITHUB_REPOSITORY_URL` with your repository's HTTPS URL. Check the second `git status` before committing: `backend/.env`, `node_modules/`, personal information, database exports, and credentials must not be staged. `.env.example` should be included. Verify the files appear on GitHub after pushing.

`.gitignore` does not erase secrets already committed. If a key was exposed, rotate/revoke it immediately in Supabase, then remove it from repository history as appropriate. Never put service-role keys, database passwords, JWT secrets, or user data in public repositories.

## Limitations and future improvements

- The app does not include password reset or email verification.
- JWTs are held in `sessionStorage` for this student MVP; an XSS vulnerability could expose a token. Keep dependencies updated and avoid unsafe HTML insertion.
- Week metrics count completed check-ins over the last seven days, not streaks.
- Future improvements could include password reset, streak summaries, CSV export, scheduled reminders, and Supabase Auth.
